# 顶部标题栏添加"自动交易：开/关"循环切换按钮

## 背景

自动交易开关的完整链路已存在：`MainWindow` 构造时已接收 `on_toggle_auto_trade` 回调（main_window.py:247），`AppController._handle_toggle_auto_trade` 会同步引擎（`engine.set_auto_trade`）和 ViewModel（`vm.setAutoTrade` → 发出 `autoTradeChanged` 信号），`MainWindow._on_auto_trade_changed` 已负责同步仪表盘复选框。因此**只需在标题栏加一个按钮接入现有回调，零引擎/控制器改动**。

## 改动

### 1. `src/presentation/theme.py`
在 `variant="danger"` 的 QSS 块后（约 line 157）新增 `QPushButton[variant="success"]` 规则（含 hover/pressed），用于"开"状态的绿色按钮（`SUCCESS #a6e3a1` + 深色文字）；"关"状态复用现有 `variant="secondary"`。

### 2. `src/presentation/main_window.py`
- **`_build_ui()` 头部区**（line 335 `addStretch(1)` 与退出按钮之间）：新增 `self._head_auto_btn = make_button(...)`，`clicked` 连接 `lambda: self._on_toggle_auto_trade(not self._vm.autoTrade)` 实现点击循环切换开/关，加 tooltip "点击切换自动交易开/关"，并按 `self._vm.autoTrade` 初始化文案与样式。
- **新增 `_sync_auto_trade_button(value)` 私有方法**：设置文案"自动交易：开 / 自动交易：关"（全角冒号）与 `variant` 属性（开=`success` 绿色，关=`secondary` 深色），切换 variant 后调用 `style().unpolish()/polish()` 刷新 QSS。
- **`_on_auto_trade_changed`**（line 452-456）：在现有复选框同步逻辑旁追加调用 `_sync_auto_trade_button(value)`，与 ConfigDialog 保存、仪表盘复选框等其它入口保持联动。

仪表盘上现有的复选框保留不动，两处通过 `autoTradeChanged` 信号自动保持一致。

### 3. `tests/test_main_window_ui.py`
新增测试方法：
- 按钮初始文案随 `vm.autoTrade`；
- 点击 `_head_auto_btn` 触发 `on_toggle_auto_trade(False/True)` 循环切换（沿用现有 `calls` 断言模式）；
- `vm.setAutoTrade(...)` 后按钮文案与 `variant` 属性同步更新（"自动交易：关" / `secondary`）。

## 验证

在 `.venv` 中运行 `python -m unittest tests/test_main_window_ui.py`（及整个 tests 目录），确认新测试与既有测试全部通过。纯 Qt UI 层改动，不涉及交易逻辑与线程边界，macOS/Windows 天然兼容。

## 说明

- 不修改交易引擎、控制器、ViewModel——状态语义（关=收到信号记为 PENDING 但不下单）完全复用现状。
- 探索中发现 `src/domain/events.py` 的 `EventBus.publish` 异常分支引用了未导入的 `sys`（潜在 NameError），与本任务路径无关，不在本次改动范围内，仅在此提示。
